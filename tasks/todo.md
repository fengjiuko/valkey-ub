## U2：实现与验证传输帧编解码

## U3：实现有界流控与 Session 状态模型

依赖：U2。范围：Session 状态实现、私有头文件、测试及构建接线。

- [x] 校验连续前缀写入、部分读取、AGAIN/EOF/ERROR 转换及重复信用。
- [x] 覆盖收到数据后关闭、错误代次/重复完成、乱序完成和有限队列容量。
- [x] 独立模型以显式完成输入验证缓冲生命周期，不引入通用 provider 抽象。
- [x] runtime 为 CREDIT 保留独立 Jetty/槽，创建前执行全局应用缓冲准入。
- [x] 生产 runtime 直接调用 liburma，握手有 5 秒超时；失败销毁保留资源待重试。
- [x] 已接受 TX 与 receive repost 停滞使用单调时钟期限，重试不续期，正常信用背压不计时。
- [ ] 接入异步设备错误处理，并在目标 provider 验证事件通知、同步调用时间上界和 DMA 终止。

验证：13 项 `UrmaSessionTest` 已通过，包括 1024 轮槽位复用和二进制字节守恒；
与协议测试一同通过 ASan/UBSan。错误地复用尚未重新投递的槽位会被变异测试检出。
流模型验证不包含硬件；runtime 另有 SDK seam 测试。U3 的剩余超时/事件项与
U4 的设备验收仍未完成。

## M2：大 String Value 显式分层设计与最小实现

## M3：权威远端层的持久化、回收与恢复

依赖：M2；用户确认故障与写入确认语义。范围：RDB、AOF、复制、回收分别拆批。

- [ ] 快照 pin、异步回收和 fencing 覆盖旧会话、旧 extent 及远端重启。
- [ ] RDB/AOF/复制保存逻辑值，不泄露指针或 Token；fork/脚本方案可执行。
- [ ] 已确认写入的故障恢复承诺经过验证，失去权威数据不按 cache miss 处理。

验证：故障恢复与快照一致性测试、重启和重放比对、lazyfree/defrag 并发测试。

## M4：直接寻址池与页/容器分层可行性

依赖：Checkpoint B 与目标平台映射能力；不自动依赖 M2 的异步实现。
范围：先写能力报告，再按分配器来源识别、特定对象/容器分别拆批。

- [ ] 实测 CPU 映射、撤销、缓存一致性、页大小和故障信号；不全局替换 zmalloc。
- [ ] 分配/释放/usable-size/defrag 路径识别来源，内存与 maxmemory 无重复计数。
- [ ] 明确“数据页”具体对象；新增 Page Manager 另立方案，不冒称已有数据库页层。

验证：目标平台映射探针、分配器/对象测试和故障注入；比较驻留容量与尾延迟。
