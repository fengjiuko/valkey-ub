# 池化与远端内存：独立研究路线

状态：研究提案，不属于首版 ConnectionType 接入的实现范围。
用户后续目标是让部分 Value、缓存或数据页使用池化、远端内存。
每个阶段需独立确认失败语义后才改变数据库行为。

## 必须区分的两类内存

| 方式 | 软件看到的对象 | 主要适配位置 |
| --- | --- | --- |
| 直接寻址的池化内存 | 经平台支持映射的 CPU 虚拟地址 | 池感知分配、释放、统计、缺页/故障处理 |
| URMA 显式访问的远端内存 | 远端 extent/handle，通过异步读写取回 | Value 表示、异步命令继续执行、缓存与版本校验 |

liburma 通信成功不等于平台提供 CPU 可解引用的远端映射。
不是所有 UB 设备/内存都可通过本地 load/store 访问；映射能力、缓存一致性、
原子性、撤销和故障信号必须在目标平台确认。
不能把远端地址或 Token 塞进本地 SDS 指针，再让 memcpy/sdsfree 访问它。

当前 Valkey 基线以对象和 SDS 等结构直接访问内存，没有一个统一的数据库
Buffer Pool/Page Manager。所谓“数据页”首先要说明是 OS 页、注册传输缓冲区、
某个容器分块，还是新引入的数据库页；新增页管理属于独立架构变化。

## 本地源码接缝与约束

| 位置 | 当前约束 | 未来需要验证的变化 |
| --- | --- | --- |
| src/zmalloc.[ch] | 分配器及 usable-size/内存统计 | 增加池专属分配与来源识别，不全局替换 zmalloc |
| src/server.h、src/object.c | 紧凑对象、embedded key/value、编码和引用 | 显式远端 handle，保持本地 objectGetVal 契约 |
| src/t_string.c、src/db.c | 命令同步取得本地对象并读取/修改 | 命令预取、暂停/恢复、重新查找及版本确认 |
| src/networking.c | 响应可能延迟消费并持有对象/缓冲 | 回复发完前固定驻留数据及其所有权 |
| src/lazyfree.c、src/defrag.c | 后台释放及本地内存移动 | 远端 extent 异步回收，避免 defrag 移动远端描述符内容 |
| src/rdb.c、src/aof.c | 序列化当前逻辑值及 fork 场景 | 输出 Value 字节，不序列化进程地址或访问凭据 |
| src/evict.c、src/expire.c | 淘汰、过期和 maxmemory | 区分本地驱逐、远端迁移与 Key 删除 |
| src/module.c | 部分接口直接返回本地 String 地址 | 提供稳定驻留视图或显式限制，不能偷改原指针契约 |

对象 encoding 当前是有限位宽，新增编码必须审计全部分支、RDB type/encoding、
OBJECT ENCODING 结果及模块可观察行为，不预先占用编码号。
既有 external memory 统计可研究复用，但不能把本地映射、远端占用、注册页
重复计数，也不能未经确认直接改变 maxmemory 的容量含义。

## M1：先验证可丢弃的远端缓存

选择有明确本地或持久化权威副本的缓存内容；远端仅保存可重建副本。
这里是新增缓存机制，当前仓库并不存在可直接打开的“远端缓存”开关。

- 元数据包含对象身份、版本、长度、校验、内存池及 extent generation。
- 命中前验证本地版本/过期状态；远端超时、损坏或丢失按 miss 处理并重建。
- 不改变已确认 SET 的持久性和复制语义。
- 先证明命中收益与额外内存/CPU 成本，再决定是否加入驱逐。

此阶段安全性较易验证，但保留权威副本时不能声称扩展了权威数据容量。

## M2：选择性大 String Value 分层

仅在单独确认容量/持久性目标后，允许部分大 String 的 payload 仅驻留远端。
Key、类型、过期、LRU/LFU 和远端 handle 保留本地。小 String、整数、嵌入值及
复杂容器首轮仍本地存储。

```text
LOCAL -> DEMOTING -> REMOTE -> FETCHING -> LOCAL
各阶段失败 -> 保留可证明正确的旧版本 / 明确错误
```

迁出使用不可变快照写新 extent；收到符合语义的写完成及内容确认后，才发布
指向该版本的 handle。传输完成不自动代表持久化完成。
原本地副本只能在快照/回复/命令引用都不再依赖它时回收。

取回先异步读取到本地 staging，检查 checksum、generation 和当前 Key 的
对象版本；Key 在等待期间被覆盖、删除、过期或重新创建时，丢弃旧取回结果。
不能持有可被主线程释放的裸对象指针，也不能把新 Key 误认成旧对象。

命令只能在没有执行副作用的阶段等待远端取回；不能执行半条命令后重跑。
GET/MGET、APPEND、SETRANGE、数值命令和比较操作均有访问路径，不能只改 GET。
Lua/Functions、MULTI/EXEC、模块回调和 fork 子进程不能直接套普通 client 的
暂停/恢复逻辑。未建立安全预取/快照机制前，该阶段不得声明支持这些组合，
也不得通过“返回空值”隐藏访问失败。

## M3：一致性、持久化与远端故障

必须先在以下两种产品语义中明确选择：

- 可重建缓存：失去远端副本等价于缓存失效，有权威副本恢复。
- 权威容量层：失去远端副本可能丢数据；须定义复制、持久化、恢复与确认时点。

对于权威层，远端故障不能当作 Key 不存在。停止/报错、从副本恢复或全量恢复
需有明确政策；“断连后回退本地”只有在仍有正确本地副本时才成立。
租约到期本身不证明旧写入者已被隔离，必须使用 fencing/generation 防止旧
会话访问已复用 extent。

RDB/AOF、复制和迁移处理逻辑值及版本，不传播进程指针或 URMA Token。
后台快照需确保对象在快照语义下可读：预驻留、快照固定或单独的安全读取通道
属于备选方案，必须测量停顿/内存成本，不能在持有普通客户端上下文时阻塞等待。
lazyfree 只提交受控回收请求；删除后的实际回收必须等待所有读写和快照 pin 解除。

## M4：池化分配与页/容器粒度

若平台提供真正可直接寻址的池化内存，先建立 pool-specific alloc/free/resize
模块，保持分配来源、对齐、usable size、NUMA、缺页及失败语义可识别。
不能对这类指针盲目调用 jemalloc free 或让 active defrag 复制后遗失来源。
进程重启、映射变化及子进程继承也需要独立方案。

有了对象粒度证据后，再评估 quicklist/listpack 等特定分块是否适合分层。
数据库统一页缓存需要新增页身份、pin/unpin、脏页/写回、恢复和访问接口；
不把这一层包装成一次小型 allocator 改动。

## 验收与推进证据

分别记录本地驻留字节、远端逻辑/物理字节、重复副本、注册内存、取回队列深度、
迁移耗时和尾延迟。固定工作集与命中率，比较容量、延迟和复制/持久化成本。
测试 Key 覆盖/过期/删除与取回交错、校验失败、extent 重用、断连、池重启、
快照并发、lazyfree 和 defrag。回归必须比较逻辑命令结果，不能只验证无崩溃。

在没有真实平台和明确故障语义前，M1–M4 都保持研究任务，不生成改变数据库
语义的开关或把 native URMA 传输测试标为远端 Value 测试。

背景参考：[UB Service Core 软件参考架构](https://www.openeuler.org/projects/ub-service-core/white-paper/UB-Service-Core-SW-Arch-RD-2.0-en.pdf)。
该文档说明池化与通信的分层，本路线的 Valkey 方案是本地设计假设，非厂商适配承诺。
