# RDMA 软件兼容与网卡适配准入方案

这是后续验证计划，当前只交付只读环境预检。共享主机的预检阶段不执行性能测试、故障注入、驱动加载、设备配置或清理。

## 结果单位

每次结果必须绑定两端各自的组合：

`应用版本/SHA + 通信后端及版本 + provider及版本 + GPU/NIC型号及固件 + 驱动/内核 + 网络协议/拓扑 + 构建与运行参数`

GPU 不参与 CPU 内存测试时填 N/A。记录实际调用链和回退情况；rdma-core 的多厂商覆盖不能替代某个优化传输、设备接口、内存注册方式或特定硬件组合的适配证据。

状态统一为：未执行、环境阻塞、测试失败、限定范围通过、不适用；不适用需说明理由。不得将未知、未执行或主项目成熟度换算成 RDMA 子系统通过。

## 分级准入

| 阶段 | 条件 | 必须保留的证据 |
| --- | --- | --- |
| G0 环境 | 构建/运行依赖、设备及普通账户权限、所选端口/IP、组合记录可核查 | 只读预检报告；权限不足不自动修复 |
| G1 最小功能 | 专用测试资源上，单客户端 PING/SET/GET 内容校验；明确使用 RDMA，限制超时 | 客户端退出码、两端日志、实际 provider/设备路径；BGSAVE 应答不能证明落盘和恢复 |
| G2 覆盖 | 单/多连接、pipeline、I/O 线程、边界/大消息分段、背压、MR 生命周期及适用的认证/复制/集群路径 | 用例、输入规模、内容校验与资源前后对比；未覆盖功能明确排除 |
| G3 恢复 | 隔离测试窗口中的进程重启、连接中断/超时及获准的链路/设备故障；校验数据与重连语义 | 故障时间线、错误、恢复时间、重复写与资源回收；禁止在预检或共用链路上注入 |
| G4 可观测 | 区分后端、CM/CQ 错误、超时/重试/回退、设备错误与业务尾延迟 | 同步时间线的应用/内核/provider/NIC记录；不能判别真实后端时不通过 |
| G5 维护 | 稳定发行版、RDMA 路径修复/issue、CI、集成矩阵和硬件表可追溯 | tag/SHA/来源/核查日期；总体仓库推送时间不替代子系统证据 |
| G6 业务试用 | 微基准及实际业务满足预先约定 SLO，并满足恢复、可观测与维护门槛 | 固定负载、重复样本、TCP对照与资源成本；结论只覆盖实际组合 |

阈值在执行前按业务目标确定。环境/provider/驱动/固件或关键路径变化后重新评估测试范围。准入是本项目验证规则，不是行业认证。

## 分别建档

| 档案 | 核查重点 |
| --- | --- |
| 软件 RXE | 只证明软件 RoCE 路径，不证明真实网卡或网络性能 |
| IB | HCA/provider、端口、子网管理及 P_Key/GID |
| RoCE | NIC/provider、GID/netdev、协议版本、交换网络配置 |
| iWARP | 对应 provider、CM/RC 语义、硬件与驱动 |
| EFA | 实例代际、驱动/provider、Libfabric及上层插件、应用所需 API；不能由设备存在推断 Valkey 当前 CM/RC 路径兼容 |
| UB / RoUB | Verbs→RoUB→URMA/UB 的 CM/QP/SGE/MR/CQ 语义及版本 |
| UB / UMS | Socket→UMS→UB；单独证明未回退 TCP，不与原生 RDMA 混算 |
| 原生 URMA | 可定位的适配代码/SHA、双端协议、构建及测试记录；本次没有交付该适配 |

IPoIB 是 IP 网络承载方式；TCP 经 IPoIB 成功不等于应用直接使用 RDMA。协议名称、NIC 名称、编程接口不能互换。

## 保留微基准与业务基准

| 层次 | 工具/负载 | 记录维度 |
| --- | --- | --- |
| Verbs | perftest 的 SEND/WRITE/READ 时延与带宽 | 版本、消息尺寸、QP/深度、GID、内存类型、CPU/NUMA |
| Valkey | 内容校验及 RDMA SET/GET 业务压测，另做 TCP 对照 | 读写比例、值长、连接、pipeline、I/O线程、p50/p95/p99、CPU/内存与错误 |
| 集合通信 | 适用平台的 nccl-tests | NCCL/插件、GPU/NIC拓扑、集合操作、消息分布、正确性、实际传输 |
| 推理 | 实际 KV 迁移、MoE/专家并行 | 框架、KV大小、专家分布、并发、TTFT/TPOT、尾延迟及恢复 |
| 存储 | 实际 I/O 与恢复场景 | 队列深度、I/O尺寸、读写比、持久性/一致性、恢复或重建 |

它们回答不同问题，不能彼此替代；CPU 内存测试不能外推到 GPU Direct。RXE 性能不能外推到物理 NIC。不承诺固定加速倍数。

## 持续跟踪与边界

候选版本晋级及关键组合变化时，复查稳定发行版、`src/rdma.c`、`deps/libvalkey/src/rdma.c`、`tests/rdma/` 和 RDMA CI 的路径级记录，保留相关 issue/PR 复现结论、上层集成矩阵及硬件兼容表。此计划没有创建定时自动化。

公开代码/官方文档不覆盖闭源栈、私有分支、全部商业支持或部署份额。本项目尚无真实 RDMA/UB 集群的测试结果。

资料入口：[perftest](https://github.com/linux-rdma/perftest)、[nccl-tests](https://github.com/NVIDIA/nccl-tests)、[EFA 官方接口与实例说明](https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/efa.html)、[Linux IPoIB 文档](https://docs.kernel.org/infiniband/ipoib.html)。这些来源在前期调查中于 2026-11-02 核查，动态版本信息需在实际测试前复核。
